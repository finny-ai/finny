# Finny AI Agent Guide

Welcome to the Finny repository. This guide is designed to help AI agents understand the infrastructure, development patterns, project structure, and core vision, ensuring consistent and correct contributions.

## ⚠️ Fork Relationship — READ FIRST

**Finny is a fork of [OpenCode](https://github.com/anomalyco/opencode)** (an AI-powered CLI tool). We regularly rebase onto upstream. To avoid breaking sync:

- **Do NOT modify upstream files unless absolutely necessary.** Each changed upstream file risks a rebase conflict. Currently only ~7 upstream files are modified for branding.
- **Add new files instead of editing existing ones.** For example, Finny-specific prompts live in `finny-*.txt` files alongside upstream prompt files.
- **Fork-only directories are safe to edit freely:** `.agents/`, `packages/finny-core/`, `packages/finny-registry/`, `packages/finny-integrations/`.
- **Upstream naming is kept intentionally:** config dir = `.opencode/`, env vars = `OPENCODE_*`, core package = `packages/opencode/`. This minimizes rebase friction.
- See `.agents/SYNC_FORK.md` for the sync workflow.

## 🎯 Core Concept & Vision

**Finny** is an AI-powered CLI for financial markets, built on top of the OpenCode TUI framework. It uses a BYOK (bring your own key) model — users provide their own AI API keys.

Finny has 3 agent modes:
- **Build**: Immediately generates trading algorithms from the user's request.
- **Research**: Asks clarifying questions before generating code.
- **Chat**: General conversational mode for financial topics and code discussion.

## 🏗️ Infrastructure & Architecture

Finny is a **Bun + Turbo** monorepo forked from OpenCode. The TUI is built with **Solid.js + @opentui/solid**.

- **Upstream Packages (inherited from OpenCode):**
  - `packages/opencode`: Core CLI, TUI, agents, session logic, and AI model integrations.
  - `packages/web`: Documentation site (Astro).
  - `packages/desktop`: Desktop application (Tauri).

- **Fork-only Packages (Finny additions):**
  - `packages/finny-core`: Finny core utilities.
  - `packages/finny-registry`: Strategy/algorithm registry.
  - `packages/finny-integrations`: External service integrations.

## 🛠️ Local Development Guidelines

- **Package Manager**: Use `bun` for all dependency installations and running scripts.
- **Run the complete app**: The primary entry for backend serving is through the `opencode` package.
  - Backend: `bun run --conditions=browser ./src/index.ts serve --port 4096` (from `packages/opencode`).
  - Frontend App: `bun dev -- --port 4444` (from `packages/app`).
- **Do not restart the app**: NEVER try to restart the app or the server process on your own unless specifically instructed.

## 💾 Database Operations (Drizzle)

- **Schema Location**: All Drizzle schemas live in `src/**/*.sql.ts`.
- **Naming Conventions**: 
  - Tables and columns use `snake_case`.
  - Join columns follow `<entity>_id` format.
  - Indexes follow `<table>_<column>_idx`.
- **Migrations**:
  - Generated by Drizzle Kit using `drizzle.config.ts`.
  - Command: `bun run db generate --name <slug>`.

## 🖥️ Frontend Operations (SolidJS)

- Always prefer `createStore` over multiple `createSignal` calls when managing complex component state.
- Be aware of SolidJS reactivity principles; do not destructure reactive props without using `splitProps` or `destructure`.

## 🤖 AI Tool Calling & Browser Automation

- **Parallel Tools**: ALWAYS USE PARALLEL TOOLS WHEN APPLICABLE to speed up operations.
- **Browser Automation**: Use `agent-browser` for web automation tasks. 
  - Core Workflow:
    1. `agent-browser open <url>`
    2. `agent-browser snapshot -i` (Extracts interactive elements with refs like `@e1`)
    3. `agent-browser click @e1` or `agent-browser fill @e2 "text"`
    4. Re-snapshot after page changes before proceeding.
