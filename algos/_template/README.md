# Algo template

This directory is the canonical layout every Finny algorithm uses. Copy it
verbatim when creating a new algo, then fill in `mission.md`, replace the
strategy stub, and grow the rest of the folder as the algo matures.

```
<algo-name>/
  mission.md          # Stable contract — what this algo is, why it exists.
  prefs.md            # Per-algo taste (sizing, risk, constraints).
  decisions.md        # Append-only HUMAN design log.
  memory.md           # Append-only AGENT summary, written only on /compact.
  CURRENT             # Single line naming the active version folder (e.g. "v01").
  data/               # Fetched market/news/SEC artifacts. Read-only for the
                      # main Finny agent; written by Data Extractor and News
                      # Agent sub-agents.
    stock/
      <SYMBOL>.parquet
    crypto/
      <SYMBOL>.parquet
    sec/
      <ticker>-<form>-<filing-date>.md
    news/
      headlines/
        <YYYY-MM-DD>.md   # One file per day. Finny lists the dir, reads
                          # only the dates it needs.
      body/
        <slug>.md         # Full article body + ## Citations section.
                          # Linked from headlines; opened on demand.
  v01/
    strategy.py       # Executable strategy.
    backtest.json     # Produced by the backtest runner (absent until first run).
    reasoning.md      # Why this version exists, what changed vs prior, disposition.
  .archive/           # Raw chat transcripts, one per day touched. Created on first need.
```

## Conventions

- Folder name is kebab-case (`hanta-biotech-swing`) and must match
  `mission.frontmatter.name`.
- `mission.md` has YAML frontmatter governed by `schema_version: 2`. The
  schemas live in `@finny-ai/core/algo`.
- `CURRENT` contains exactly one token, the version directory name. No JSON,
  no YAML, no comments.
- Version dirs are zero-padded two digits: `v01`, `v02`, …, `v99`. This
  keeps lexicographic sort correct past `v09`.
- `backtest.json` is not created until a backtest runs. All eight metric
  fields are required (`null` is acceptable for genuinely unmeasurable).
- `.archive/` chat transcripts are never deleted. The compaction flow
  (see `finny-memory` plugin) produces a derived view in `memory.md`;
  the source stays here.

## memory.md vs decisions.md

Two append-only logs that look similar but serve different writers and
audiences. Keep them straight:

- **`decisions.md`** — *human* voice. You write here when you make a
  material design decision ("kill the stop-loss because the regime
  changed", "we're freezing the universe to large-cap only"). One entry
  per decision, chronological.
- **`memory.md`** — *agent* voice. Written exclusively by the Finny agent
  during `/compact`, via the `finny_record_memory` tool. Each entry
  summarizes everything since the last compaction so a fresh session can
  pick up cold. Humans do not edit this file.

## Versioning rules (vNN)

Versions mark **structural intent change**, not promotion events. Tuning
parameters is an in-place edit; ripping out the stop-loss is a new `vNN+1`.

- **User-gated.** Finny does not autonomously spawn `v(n+1)`. New versions
  only happen when the user explicitly asks for a structural change.
- **Iteration is in place.** Finny edits the active version's `strategy.py`
  while drafting. It does not create version folders mid-iteration.
- **Creation sequence on user-approved structural change:**
  1. Compute next `vNN` (`max(existing) + 1`, zero-padded to 2 digits).
  2. `mkdir <algo>/v{NN+1}/` — empty.
  3. Write `strategy.py` (the newly accepted code).
  4. Flip `CURRENT` to `v{NN+1}` atomically (write temp, then rename).
  5. Write `reasoning.md` (why this version exists, diff from prior).
  6. Backtest runner produces `backtest.json` asynchronously.

## data/ contract

The `data/` subtree is owned by sub-agents, not the main Finny agent.

- **Writers:** Data Extractor (prices, SEC filings), News Agent (headlines + bodies).
- **Reader:** the main Finny agent. It must not edit, delete, or fetch into
  `data/` directly — invoke the relevant sub-agent instead.
- **News progressive disclosure.** Always start with the daily headlines
  file (`data/news/headlines/<date>.md`). Open `body/<slug>.md` only when
  you need the full article. This keeps context usage proportional to
  actual interest.

## Strategy API & runner shapes

Three strategy shapes coexist in the codebase. The backtest runner
(`engine_v2/cli.py`) auto-detects which shape a strategy uses and wires
it to the appropriate adapter. **Read this table before writing a new
strategy.**

| Shape | Constructor | Method | Order API | Location | Usage |
|-------|-------------|--------|-----------|----------|-------|
| **A** — v1 legacy | `__init__(config_path, broker, market)` | event-driven | `broker.submit_order(Order(...))`, `market.candles(...)` | `packages/opencode/strategy.py` | Live Alpaca/Algoclash |
| **B** — engine_v2 native | `__init__(broker, market, config)` | `on_bar() -> dict` | `broker.submit_order(V2Order(...))` | `engine_v2/runtime/strategy_api.py` | Future |
| **C** — backtest canonical | `__init__(broker, params=None)` | `on_bar(symbol, bar)` | `broker.buy/sell/position/cash/equity/price` | Template, `strategies/*/strategy.py` | **Every new algo** |

### Shape-C bar dict

```python
bar = {
    "open":       float,      # current decision-time-safe open
    "prev_open":  float|None, # completed prior bar
    "prev_high":  float|None,
    "prev_low":   float|None,
    "prev_close": float|None,
    "volume":    float,
    "timestamp": int,     # unix nanoseconds
    "symbol":    str,
}
```

### Loader discovery order

1. Strict v2: module has `Strategy(broker, params=None)` and `on_bar(self, symbol, bar)` → **Shape C**
2. Explicit `v1_compat` only: module has `EthTrendBreakoutStrategy` → **Shape A**
3. Neither found → error with helpful message

## Where algos live

User-owned algorithms live under
`${XDG_DATA_HOME:-$HOME/.local/share}/finny/algos/` (or
`%LOCALAPPDATA%\finny\algos\` on Windows). Only this template ships in the
repo.
